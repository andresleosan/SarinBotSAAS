# Platform WhatsApp HTTP restoration

Restores the four frozen v24 routes and existing isolated retry observer on the reviewed R2/R3a foundation. All admin methods use the existing revocation-aware superadmin guard before parsing or effects. Responses preserve exact envelopes, errors, no-store headers and Node/dynamic exports.

Ordinary webhooks retain raw-byte signatures with inclusive ±300-second freshness, exact company scope filtering and lazy persistence. Diagnostic configuration takes precedence without fallback. The diagnostic alone retains its no-age HMAC, process/Database pinning, singleton lifecycle, 32-request/2-concurrent/16-attempt limits, collision handling and exact late verdicts. Its authenticated summary retains the frozen bounded attempt array; administrative close clears that array without resetting process state.

Validation uses synthetic data only: meaningful preimplementation behavioral failures with resolved placeholders, focused observer/route/integration tests, affected existing auth/HTTP/reader tests, TypeScript, and an isolated hash-pinned differential observer comparison. No live service, credentials, application server or provider operation was used. Private evidence records exact commands, counts, provenance and limitations.

This cut does not establish a complete baseline, live provider compatibility or production deduplication. P0 remains open and nondeployable; UI, Worker/retention integration and final parity gates remain separate work.
