# SarinBot public WhatsApp automation contract

Implementation evidence is synthetic and dated 2026-10-21. Processing, transcription, AI and sending default OFF; daily budgets default zero. The deployment remains one application process with the existing shared inference queue. No account, key, budget, circuit, tariff or verified response mapping was configured by this change.

## Public support and spending

Public support reads finite versioned support facts and `readPublicCommercialOffer` only. It never enters the private admin copilot or reads payments, receipts, businesses or commercial conversation history. The Spanish prompt treats input as data. Responses require strict JSON, at most 1024 UTF16 units / 4096 UTF8 bytes, unique known source IDs and no tools, HTML or URL claims. Source membership and finite validation do not prove semantic grounding of every sentence.

The actual dispatcher binds source actor, question, lease and abort signal through private asynchronous context. Context alone grants no authority. Inside the commercial queue's NORMAL slot it rechecks current Firebase/source/connection authority, freezes the request, reserves a request-bound quote and consumes a durable once-only permit. A private runtime capability binds exact bytes/signal/attempt and is consumed before the common DeepSeek transport. Commercial `completeChat` retains its paid context and business quota gates.

Requests use `deepseek-flash`, disabled thinking, no tools, 4096 output tokens and at most 128000 serialized UTF8 bytes. Input upper bound is bytes + 4096. Each cost component is rounded up separately using integer arithmetic: input 300/1000 and output 1200/1000 microUSD per token. The persisted quote has a keyed request digest, byte count, bounds, model policy fingerprint and maximum; no prompt plaintext. Policy identity includes the tariff/version/rates and exact verified response identifiers. Optional `PLATFORM_WHATSAPP_GENERATION_POLICY` is closed when absent, malformed or its response mapping is empty. No default wire identifier is inferred from a public model alias.

Missing/unrecognized response model or invalid usage keeps the entire uncertain hold and creates no generated outbox. Known usage on invalid output is settled once without repair inference. Overrun records actual cost and blocks the circuit. One generation-token telemetry observation uses `sarin_platform_support` and `businessId:null`; it cannot charge commercial counters or repeat the attempt.

Sending additionally requires a strict `sendEvidence` in `PLATFORM_WHATSAPP_TARIFF_POLICY`: version equal to tariff version, currency `USD`, timezone `UTC`, category `service`, destinationScope `all_e164`, and a positive rational rate exactly equal to `tariff.send`. It declares a trusted global conservative upper bound, not provider entitlement or verification. Absent/mismatched evidence closes new send claims, reservations and start, including recovery. Exact destination remains encrypted in the original outbox, bound by the keyed conversation/contact digest and original job/source/scope; only the once-returned permit payload is sent. Acceptance/status is not cost evidence: started send holds remain unknown.

Synthetic examples only (not verified production values): generation mapping `{ "version":"synthetic-verified-v1", "responseModels":["synthetic-wire-model-v1"] }`; send evidence `{ "version":"synthetic-v1", "currency":"USD", "timezone":"UTC", "category":"service", "destinationScope":"all_e164", "rate":{"numerator":1,"denominator":1} }` with matching synthetic tariff version/rate. Production values require separate verification and authorization.

## YCloud transport and observations

The dedicated optional `PLATFORM_YCLOUD_API_KEY` is never returned in public configuration. Requests use fixed `https://api.ycloud.com/v2`, `X-API-Key`, redirect rejection, no cache, no retries and bounded JSON. Two GETs inspect exactly `/whatsapp/businessAccounts/{wabaId}` and `/whatsapp/phoneNumbers/{wabaId}/{phoneE164}`. All returned resource IDs must match the configured scope. Observation time is local request start; the combined observation has a 10-second deadline. Send uses a 15-second deadline clipped by the original job signal.

Positive readiness is Sarin's conservative local policy: phone CONNECTED; WABA APPROVED / REINSTATE; explicitly empty restrictions; paymentMethodAttached true; no removal evidence. Optional phone updateEvent must be ACCOUNT_RECONNECTED. This can reject otherwise operational accounts. Exact DISCONNECTED / ACCOUNT_OFFBOARDED or recognized removal facts are negative. Missing identity, 404, unknown state or failed lookup is indeterminate and invalidates usable evidence. Serialized scope observations and revision CAS discard stale results. Reconnect never clears pause or revives work. Freshness must be strictly less than five minutes at each effect permit. Signed first ordinary input can refresh observation before admission; echo and exact SALIR stay priority, and observation failure preserves human reception.

`POST /whatsapp/messages/sendDirectly` sends one interactive reply-button body from fixed own scope to the permit destination, with at most three menu buttons and the original outbox UUID as externalId. There are no templates, media sends, discovery, message GET recovery, or retry transports. externalId is not provider idempotency. Ambiguous dispatch never generates substitute text or another send.

Acceptance and the provider-ID alias are persisted in the same transaction. Signed sparse statuses retain supplied scope fields as optional, without fabricating omitted provider facts. Only the fixed-scope provider-ID alias locates an existing outbox; supplied WABA/from/to/externalId conflicts are rejected. Unknown IDs and forged externalId cannot repair an unknown send. Delivery success advances monotonically, failure remains sticky, and neither updates TTL, cost, consent or menu authority. The cleaner validates aliases and targets before bounded deletion; malformed pages remain honestly incomplete.

## Lifetime and recovery

One coalesced drain and abort registry run bounded outbox recovery before new inference. Prepared/claimed rows can continue only through a new confirmed send permit; started/unknown/terminal rows never dispatch again. UUIDs, tokens, output fingerprints and original deadlines are preserved. The sole Node lease renewal is every 20 seconds for a 60-second lease within the immutable 120-second processing deadline, including audio and queue waits. Cancellation/revocation/echo/connection changes fence durable work and abort owned operations. Recovery uses one activity-only unref 30-second timer; empty work stops it. Existing Worker cron uses bounded strict durable potential-work checks and wakes only the existing singleton; commercial wake remains independent and is coalesced to one start.

Strict wake and unsent recovery scan at most four pages of 25 candidates per status using stable identity cursors. Expired or stale-authority rows consume that finite scan budget but never supply wake authority. The drain tracks progress across advance, leased, reply_saved and ready pages, returning to outbox recovery after cleanup, with at most 100 passes. Malformed cursor rows or live work beyond the scan budget can still prevent a positive scheduling proof; no unbounded scan or expired-row wake fallback is used.

The accepted A4 Node adapter owns audio reservation and transcript commit; Worker owns audio settlement. A5 delegates that actual path and adds no second reservation, settlement or renew loop. El audio bruto se procesa en memoria y no se conserva en R2 ni en la bandeja. La transcripción es contenido de una consulta. Nunca prueba identidad, acepta documentos ni autoriza un pago. Encrypted content/contact keep original 24-hour expiry; minimal control records remain at most 30 days.
